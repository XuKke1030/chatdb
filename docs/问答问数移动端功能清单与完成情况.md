## 总体结论

当前项目已经具备 UIAP 登录与权限主动获取、AIDGP 车流/人流/网格/知识库数据主动同步、后台同步日志、重试、连通性测试、数据新鲜度与对账等后端基础能力。主题入口、按权限展示主题、按权限返回异常告警、告警点击自动提问所需后端接口已完成。车流与网格的生产化链路推进较明显，已经有 AIDGP 同步、落库、预聚合表与快问查询的闭环雏形。

主要差距集中在三类：

1. 移动端前端交互待验证：主题入口、输入框、语音、澄清选项、卡片切换、复制、停止生成、参考资料面板等多数 UI 行为需要到 `D:\code\morphic-main` 检查。
2. 人流问数仍弱于车流/网格：已有表结构和部分快问能力，但年龄、性别、户籍、来源地、标签组合、占比类问题还没有完整查询闭环。
3. 问答知识库能力已有检索、引用、权限和 AIDGP 同步框架，但附件解析、版本识别、文件联动、引用跳转精确定位、联网搜索真实供应商等仍需补齐。

## 建议开发计划

### 第一阶段：前端核验与接口对齐，1-2 天

1. 在 `D:\code\morphic-main` 对照本文逐项检查移动端入口、问数页、问答页、后台页。
2. 输出前后端接口差异清单，重点确认 topic、permission、knowledgeBase、citation、chart metadata 字段。
3. 完成基础联调用例：UIAP 登录、主题权限、车流快问、网格快问、问答引用。

### 第二阶段：人流生产化，3-5 天

1. 完成 AIDGP 人流字段口径确认，补齐年龄、性别、户籍、来源地、流动人口标签。
2. 新增或完善人流标签聚合表，支撑占比、TopN、趋势、峰值、综合分析。
3. 扩展人流 fast path 与图表返回结构，覆盖 Excel 中人流典型问法。

### 第三阶段：网格问法补齐，2-3 天

1. 基于 `grid_metric_monthly` 补齐趋势、占比、均值、处理时长、跨类别对比。
2. 完善重大案件评分和全流程效能分析口径。
3. 对自然语言月份、社区、案件类别、状态条件做统一解析。

### 第四阶段：车流高级问法补齐，2-3 天

1. 完成省内/省外/港澳/外地车分类口径。
2. 补齐同比、环比、节假日对比、停留时长分布桶。
3. 对来源地排名和车牌归属地做抽样校验。

### 第五阶段：问答知识库增强，3-5 天

1. 补附件解析流水线：PDF、Word、图片 OCR、切片、向量化。
2. 补版本识别：生效日期、废止关系、同名文件多版本优先级。
3. 补引用精确跳转、参考资料面板、文件联动推荐和联网搜索真实供应商。

### 第六阶段：验收与对账，2 天

1. 为每个 Excel 典型问法准备固定验收问题和期望结果。
2. 建立 AIDGP 同步数据量、聚合数据量、查询结果三方对账。
3. 输出 P0 功能验收报告，剩余 P1/P2 功能进入迭代池。
