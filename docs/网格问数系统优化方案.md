## 二、核心问题归纳

### 问题 A：表名/字段名泄露到用户回答（最严重）
- **表现**：`case_list`、`pending_step`、`report_time`、`update_time`、`case_source` 反复出现在特征洞察的"统计口径"描述中，包括括号备注形式如"网格平台（case_list）""处理步骤（pending_step）"
- **根因**：prompt 虽禁止了，但 AI 写统计口径时习惯用括号备注英文来源，这是训练数据的模式，LLM 对否定指令的遵守率约 85-95%
- **方案**：见 P1

### 问题 B：回答结构不稳定
- **表现**：同一个排名问题，有时只输出图表无文字，有时完整四段，有时缺精准结论或洞察分析
- **根因**：prompt 对结构完整性的约束不够强硬，AI 走 CoT 时可能中途判定"简洁输出"而跳段
- **方案**：见 P2

### 问题 C：Agent 步骤浪费导致超限
- **表现**：AI 对已知表结构仍反复执行 `DESCRIBE`、`SHOW COLUMNS`、`SHOW TABLES`，6-10步用于探查，剩余步骤不够业务查询
- **根因**：prompt 说"在不了解库表结构时，必须先查询"，AI 把所有请求都当"不了解"处理
- **方案**：见 P3

### 问题 D：前端图表 topN 截断未生效
- **表现**：问"前三"时图表仍显示5条或全部
- **根因**：前端 topN 逻辑代码已写好，但热更新可能未完全生效
- **方案**：已修复，需验证

### 问题 E：空数据导致 Agent 流崩溃
- **表现**：SQL 查询返回0行时，`ConvertAnyToMarkdownTable` 返回 error，整个 Agent 流中断
- **根因**：空结果作为错误向上抛出，应作为正常业务文本处理
- **方案**：已修复，需验证

## 三、具体优化方案

### P1：彻底消除表名/字段名泄露

**方案：代码层后置过滤，而非仅靠 prompt 约束**

- **位置**：`internal/logic/ai/chan_out.go` 的 `AiChatStreamOut` 函数，在将 AI chunk 写入 respChan 之前
- **做法**：新增 `sanitizeOutput(text string) string` 函数，用正则匹配并替换：

| 原始值 | 替换为 |
|--------|--------|
| `case_list` | `案件记录` |
| `grid_case_record` | `案件记录` |
| `grid_metric_daily` | `案件统计` |
| `grid_metric_monthly` | `案件统计` |
| `pending_step` | `当前环节` |
| `report_time` | `上报时间` |
| `update_time` | `更新时间` |
| `case_source` | `案件来源` |
| `case_type` | `案件类别` |
| `case_type1` | `一级类别` |
| `case_type2` | `二级类别` |
| `case_status` | `处置状态` |
| `population_tag_daily` | `人口统计` |
| `traffic_gate_record` | `过车记录` |
| `metric_date` | `统计日期` |
| `metric_month` | `统计月份` |
| `responsibility_unit` | `责任单位` |
| `community` | `社区` |
| `region` | `区域` |

- 括号备注形式处理：
  - `（case_list）`、`(case_list)`、`（pending_step）`、`(pending_step)` → 整体删除
  - 正则：`[（(]\s*[a-z_]+\s*[）)]`
- 同时保留 prompt 层的禁止规则（双保险）

### P2：强制回答结构完整性

**方案：在 prompt 的回答结构部分增加"分段输出"指令**

在 `main.md` 的回答结构部分增加：

```
**结构完整性硬规则**：
- 只要用户发起正式问数（而非澄清），**精准结论、特征洞察、洞察分析三段必须全部输出**，不能省略任何一段。
- 可视化段按规则判断：趋势、多对象对比、多值排名、构成占比、明细列表时输出；单一数值、单一占比、数据为空时不输出。
- 不能只输出图表而不输出文字结论，也不能只输出文字而不输出符合条件的图表。
- 即使问题简单（如单指标问数），也必须保留四段结构；精准结论只需一句，特征洞察说明口径即可，洞察分析可精简为1条，但不能省略。
```

增加 few-shot 正反例对比：

```
✗ 错误：只输出 ```chatdb-chart 代码块没有文字
✓ 正确：先输出 ## 精准结论 给出文字结论，再输出 ## 可视化 给出图表

✗ 错误：特征洞察中写"来源于 case_list 表"
✓ 正确：特征洞察中写"来源于案件记录"
```

### P3：减少 Agent 探查步骤浪费

**方案：三层防护**

#### 3.1 Prompt 层（已完成部分）

在 `grid.md` 和 `main.md` 中明确：
- 主题 prompt 已列出表结构时，直接使用这些信息编写 SQL
- 不要再执行 DESCRIBE / SHOW COLUMNS / SHOW TABLES
- 每多执行一步探查就多消耗一步额度，容易导致步骤超限失败

#### 3.2 Few-shot 示例

在 `grid.md` 中增加完整的"问题→SQL"示例，让 AI 学会直接写业务 SQL：

```
### 查询示例（直接写SQL，无需先探查表结构）

问"4月上报案件社区排名前三"：
SELECT COALESCE(NULLIF(region,''), '未知') AS name, COUNT(*) AS total
FROM case_list
WHERE report_time >= '2026-04-01' AND report_time < '2026-05-01'
GROUP BY name ORDER BY total DESC LIMIT 3

问"5月案件来源占比"：
SELECT COALESCE(NULLIF(case_source,''), '未知') AS name, COUNT(*) AS total
FROM case_list
WHERE report_time >= '2026-05-01' AND report_time < '2026-06-01'
GROUP BY name ORDER BY total DESC

问"各社区4月上报量对比"：
SELECT COALESCE(NULLIF(region,''), '未知') AS name, COUNT(*) AS total
FROM case_list
WHERE report_time >= '2026-04-01' AND report_time < '2026-05-01'
GROUP BY name ORDER BY total DESC LIMIT 10

问"案件积压主要在哪些环节"：
SELECT COALESCE(NULLIF(pending_step,''), '未知') AS name, COUNT(*) AS total
FROM case_list
WHERE pending_step NOT LIKE '%结案%'
GROUP BY name ORDER BY total DESC
```

#### 3.3 代码层

在 Agent tool call 的中间件中，如果检测到连续 3 次执行 `DESCRIBE`/`SHOW` 类型 SQL，自动将表结构信息注入下一次 prompt，避免继续探查。

实现位置：`internal/logic/ai/chat.go` 中 Agent 的 tool call 回调处，维护一个计数器，连续探查SQL达到阈值时，将 `grid.md` 中的表结构段落自动追加到下一次用户消息中。

## 五、各问答类型的回答标准对照

| 类型 | 标准要求 | 当前差距 | 改进方向 |
|------|---------|---------|---------|
| 单指标问数 | 直接给数值，简洁明了 | 空数据时崩溃 | P5 验证 |
| 占比 | 给占比+补充同类型对比 | 基本达标，缺可选对比 | prompt 补充示例 |
| 排名 | 降序列出TopN，可补充排名变化 | 图表topN未生效，结构不稳定 | P2 + 前端修复 |
| 均值 | 给均值+口径+最高最低对比 | 未测试 | — |
| 多维度对比 | 按维度展示，对比关键项，自动生成图表 | 图表数据过多，表名泄露 | P1 + 前端topN |
| 趋势 | 时间节点数据+升降幅度+折线图+趋势结论 | 未测试 | — |
| 时段分布 | 时段分布+高峰标注+图表+特征总结 | 未测试 | — |
| 多维度综合分析 | 整体结论→分维度拆解→可视化→业务洞察 | 表名泄露 | P1 |
| 跨类别对比 | 对比维度→核心指标→关键差异→对比图表→原因分析 | 表名泄露 | P1 |
| 全流程效能 | 拆解环节→按环节展示指标→差异标注→流程图→优化建议 | 步骤超限 | P3 |
| 模糊提问 | 自动识别→标准化回答→歧义触发确认 | 步骤超限 | P3 |
