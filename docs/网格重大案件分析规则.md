# 网格重大案件分析规则

> 适用接口：`GET /api/v1/grid/major-case-analysis`  
> 适用场景：问数中“重大案件、重点案件、影响最大、处置最难”等问题。  
> 当前版本：第一版可解释规则评分。后续可根据业务反馈调整分值或迁移到后台配置。

## 一、重大案件定义

重大案件不是简单按最新案件排序，而是从影响范围、处置难度、时效风险和重复情况综合判断。

第一版等级规则：

| 综合评分 | 等级 |
| --- | --- |
| 80 分及以上 | 重大 |
| 60-79 分 | 重点关注 |
| 40-59 分 | 一般关注 |
| 40 分以下 | 普通案件 |

## 二、评分公式

```text
重大案件综合评分 = 影响度分 + 处置难度分 + 时效风险分 + 历史重复加分
```

综合评分最高 100 分。

## 三、评分维度

### 3.1 影响度分

| 规则 | 分值 |
| --- | --- |
| 案件类别或描述属于安全、应急、消防、燃气、污染、群体投诉、城市运行类 | +30 |
| 描述中包含多人、群体、反复、投诉、隐患、危险、停电、堵塞等关键词 | +20 |
| 涉及地基下沉、路面塌陷、裂缝、危房、坍塌、结构安全等高危隐患 | +20 |
| 来源或描述包含媒体、舆情、督办、热线、信访等关注渠道 | +15 |
| 涉及住宅小区、居民、楼栋、物业、建筑物、房屋等民生场景 | +10 |

### 3.2 处置难度分

| 规则 | 分值 |
| --- | --- |
| 责任单位为空或责任主体不明确 | +20 |
| 责任单位涉及多个主体，存在跨部门协同难度 | +20 |
| 涉及协调、权属、历史遗留、疑难、无法、困难、拒不整改等关键词 | +20 |
| 当前仍处于待办、派遣、处理中、未处理等处置链路 | +10 |
| 描述存在重复、反复、多次、持续等表述 | +10 |

### 3.3 时效风险分

| 规则 | 分值 |
| --- | --- |
| 未结且上报超过 3 天 | +20 |
| 未结且上报超过 7 天 | +30 |

### 3.4 历史重复加分

| 规则 | 分值 |
| --- | --- |
| 同区域、同类别存在 3 条及以上重复案件 | +10 |
| 同区域、同类别存在 5 条及以上重复案件 | +20 |

## 四、数据优先级

1. 如果 `grid_case_record` 有数据，优先使用 AIDGP 同步后的 `grid_case_record`。
2. 如果 `grid_case_record` 暂无数据，兼容旧表 `case_list`。

## 六、移动端展示建议

移动端固定展示结构：

1. 顶部结论：当前最需要关注的案件、综合评分和等级。
2. 案件卡片：案件编号、区域、类别、状态、上报时间、责任单位。
3. 评分拆解：影响度、处置难度、时效风险、综合分。
4. 判定依据：展示 3-5 条主要原因。
5. 处置建议：展示 1-3 条建议。

## 七、验收口径

后端完成标准：

- 支持 `grid_case_record` 优先查询。
- 支持影响度、处置难度、时效风险、历史重复四类规则。
- 返回 Top1 案件、评分拆解、等级、判定依据和处置建议。

前端完成标准：

- 用户在网格主题问“重大案件”类问题时，能看到固定模板回答。
- 展示评分拆解、等级、依据和建议。
- 数据为空时展示明确提示。
