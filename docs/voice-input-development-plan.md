# 智慧问数语音提问开发方案

## 1. 目标

智慧问数的网格、人流、车流三个模块共用同一套问题输入区，能力保持一致：

- 文本输入限制 100 字。
- 支持一键发送。
- 支持回车发送，Shift + Enter 换行。
- 发送后输入框自动清空。
- 回答生成中再次点击发送按钮可停止回答。
- 支持语音录入，自动转写为文字后填入输入框并发送。
- 静默超时后自动停止录音。

## 2. 当前基础

当前前端问数页 `AskNumberChat` 已完成：

- 100 字限制。
- 回车发送。
- 发送后清空。
- 回答中停止。
- 网格、人流、车流通过 `topic` 区分。

后续语音提问应直接扩展该输入区，不为三个主题分别重复实现。

## 3. 推荐实现路线

### 3.1 MVP 方案：浏览器 Web Speech API

适合快速演示和低成本验证。

前端能力：

- 使用 `window.SpeechRecognition` / `window.webkitSpeechRecognition`。
- 设置 `lang = 'zh-CN'`。
- 点击麦克风按钮开始录音。
- 识别结果返回后写入输入框。
- 如果识别文本非空，自动提交问题。
- 监听 `onspeechend`、`onend`、`onerror` 做状态恢复。
- 设置静默计时器，例如 3 秒无识别结果自动停止。

优点：

- 不需要新增后端接口。
- 开发速度快。
- 适合先跑通交互闭环。

限制：

- iOS、部分 WebView 和国产浏览器兼容性不稳定。
- 识别服务依赖浏览器厂商。
- 无法统一控制识别质量和隐私策略。

结论：可作为第一版，但不建议作为最终生产方案。

### 3.2 生产方案：前端录音 + 后端 ASR

适合正式上线。

前端：

- 使用 `navigator.mediaDevices.getUserMedia({ audio: true })` 申请麦克风权限。
- 使用 `MediaRecorder` 录制音频。
- 支持录音状态：idle、recording、transcribing、error。
- 使用 Web Audio API 检测音量，实现静默超时。
- 静默超过 2.5-3 秒自动停止录音。
- 停止后将音频 Blob 上传到后端 ASR 接口。
- 后端返回文字后填入输入框。
- 如果文字长度超过 100 字，前端截断并提示。
- 默认自动发送，也可配置为“转写后等待用户确认”。

后端：

- 新增接口：

```txt
POST /api/v1/speech/transcribe
Content-Type: multipart/form-data

file: audio/webm 或 audio/wav
topic: grid | population | traffic
```

返回：

```json
{
  "text": "本月高新区案件办结率是多少",
  "durationMs": 4200,
  "language": "zh-CN"
}
```

ASR 服务可选：

- 云服务：阿里云、腾讯云、讯飞、火山、百度。
- 大模型接口：OpenAI Whisper 类接口、DeepSeek 暂无原生 ASR 时需接第三方。
- 私有化：Whisper / faster-whisper 部署为内网服务。

## 4. 前端交互设计

输入区按钮建议：

```txt
[麦克风] [输入框] [字数 0/100] [发送/停止]
```

状态说明：

| 状态 | 麦克风按钮 | 发送按钮 | 输入框 |
|---|---|---|---|
| idle | 可点击开始录音 | 有文本时可发送 | 可输入 |
| recording | 高亮，点击停止 | 禁用或保持停止回答逻辑 | 可禁用或保留 |
| transcribing | loading | 禁用 | 显示“正在转写...” |
| answering | 可禁用 | 变为停止按钮 | 可输入下一问或禁用 |
| error | 恢复默认 | 恢复默认 | 显示错误提示 |

建议交互：

- 点击麦克风开始录音。
- 录音时再次点击麦克风停止录音。
- 用户静默超过阈值自动停止。
- 转写成功后自动发送。
- 转写失败时提示“语音识别失败，请重试或手动输入”。
- 麦克风权限拒绝时提示“请开启麦克风权限后重试”。

## 5. 静默检测方案

使用 Web Audio API：

1. `AudioContext.createAnalyser()` 获取音频频谱。
2. 每 100ms 计算当前音量均值。
3. 当音量低于阈值，例如 `0.02`，开始累计静默时长。
4. 静默超过 3000ms 自动停止录音。
5. 如果检测到有效声音，重置静默计时。

需要注意：

- 前 800ms 可设为宽限期，避免刚开始录音就停止。
- 最大录音时长建议限制为 30 秒。
- 音频过短，例如低于 500ms，直接提示重新录入。

## 6. 后端接口设计

### 6.1 API 定义

```go
type SpeechTranscribeReq struct {
    g.Meta `path:"/speech/transcribe" method:"post" tags:"V1/语音" sm:"语音转写"`
    File  *ghttp.UploadFile `type:"file" v:"required#音频文件不能为空"`
    Topic string            `json:"topic" dc:"主题：grid|population|traffic"`
}

type SpeechTranscribeRes struct {
    Text       string `json:"text"`
    DurationMs int   `json:"durationMs"`
    Language   string `json:"language"`
}
```

### 6.2 后端处理流程

1. 校验用户登录状态。
2. 校验用户是否有对应 `topic` 权限。
3. 校验文件大小，例如最大 10MB。
4. 校验音频格式：webm、wav、mp3、m4a。
5. 上传或转发给 ASR 服务。
6. 获取转写文本。
7. 截断到 100 字或返回给前端处理。
8. 记录必要日志：用户、topic、耗时、成功/失败，不记录敏感原始音频内容。

## 7. 安全与合规

- 麦克风权限必须由用户主动点击触发。
- 前端必须显示录音状态。
- 录音文件默认不落盘，除非业务明确要求留存。
- 如果必须留存，应配置保留周期、脱敏策略和访问权限。
- ASR 调用失败不能影响文本输入能力。
- 服务端限制文件大小和请求频率，避免滥用。

## 8. 验收标准

文本输入：

- [ ] 网格、人流、车流三个模块均共用输入区。
- [ ] 输入最多 100 字。
- [ ] 回车发送。
- [ ] 发送后输入框清空。
- [ ] 回答中点击发送按钮停止回答。

语音提问：

- [ ] 点击麦克风开始录音。
- [ ] 再次点击麦克风停止录音。
- [ ] 静默 3 秒自动停止。
- [ ] 转写成功后自动填入输入框并发送。
- [ ] 转写文本超过 100 字时截断或提示。
- [ ] 麦克风权限拒绝时有明确提示。
- [ ] ASR 失败时不影响手动输入。
- [ ] 三个主题都会携带正确 `topic`。

## 9. 推荐开发顺序

1. 前端抽出通用 `QuestionInputBar` 组件。
2. 将网格、人流、车流问数页统一使用该组件。
3. 增加麦克风按钮和录音状态。
4. 先接 Web Speech API 做 MVP。
5. 新增后端 `/api/v1/speech/transcribe` 接口。
6. 替换为生产 ASR 服务。
7. 加入静默检测、最大录音时长、权限错误提示。
8. 完成测试和移动端真机验证。
