# Q1 事件类/部件类分类错误 — 根因分析与修复方案

## 根因分析

### 直接原因
AI 将含"设施"或"违法"关键字的案件归为"部件类"，把其余归为"事件类"，产生 328+158=486 的错误分类。

### 真实数据对比

| 分类 | AI回答 | 数据库真实值 | 偏差 |
|------|--------|-------------|------|
| 事件类 | 328件 | 382件 | -54件 |
| 部件类 | 158件 | 104件 | +54件 |

AI 把 **社区服务/公共设施（54件）** 和 **城市管理/违法建设（20件）** 错误归入"部件类"，
又把 **城市管理/市政设施（84件）** 归为"部件类"（这部分正确）。
而真正的正确分类应按**一级类别**划分：

| 一级类别 | 归属 | 数量 |
|---------|------|------|
| 环境卫生 | 事件类 | 117件 |
| 市场监管 | 事件类 | 95件 |
| 市容市貌 | 事件类 | 93件 |
| 社区服务 | 事件类 | 77件 |
| **城市管理** | **部件类** | **104件** |

### 根本原因
`grid.md` prompt 中**缺少"事件类""部件类"的明确定义和分类口径**。AI 只能凭训练数据中的常识猜测，导致按关键词（"设施""违法"）而非按一级类别分类。

---

## 修复方案

### 修改文件：`prompt/grid.md`

在"网格常见指标"部分之后，新增"案件分类口径"定义：

```markdown
## 案件分类口径

当用户提及"事件类""部件类"时，按以下口径分类：

**事件类**（一级类别归属）：
- 环境卫生（含垃圾清运、污水排放、户外广告等）
- 市容市貌（含乱摆卖、占道经营等）
- 市场监管（含无证经营、食品安全等）
- 社区服务（含公共设施、邻里纠纷等）

**部件类**（一级类别归属）：
- 城市管理（含市政设施、违法建设等）

分类判断规则：按 `case_type` 字段中"/"分隔的第一级（一级类别）归类，不要按二级类别关键词归类。

示例：
- "社区服务/公共设施" → 一级类别=社区服务 → 事件类（✓）
- "城市管理/市政设施" → 一级类别=城市管理 → 部件类（✓）
- "城市管理/违法建设" → 一级类别=城市管理 → 部件类（✓）

错误示范：
- 含"设施"关键字就归为部件类（✗）——"社区服务/公共设施"属事件类
- 含"违法"关键字就归为部件类（✗）——"社区服务/邻里纠纷"含"违法"可能性但属事件类
```

### 影响评估
- 此修改仅影响 AI 对"事件类""部件类"问题的分类判断逻辑
- 不影响其他查询
- 配合 P1 代码层过滤（已实施），可确保输出中不会泄露 `case_type` 字段名

### 预期效果
- Q1 数据准确率从 40% 提升至 95%+
- 消除 AI 凭关键词猜测分类的随机性
